## Discoveries and friction

1. **PATH is session-scoped.** The isolated installation requires its bin directory on PATH in each new terminal. A missing command in a new terminal is not proof of a failed installation.
2. **Development serving occupies the terminal.** Ctrl+C stops the server. The dashboard server was started and stopped twice; it must remain running while browsing and editing from another terminal.
3. **Counter wording can be mistaken for build history.** The basic starter's "Built 7 times" is an in-memory button counter, not seven production builds. Candidate improvement: clearer demo wording. No change made.
4. **Unused assets are copied to output.** KIT00's replacement HTML does not load app.js, but the old counter script remains in src and therefore dist. This is an observed static-copy behaviour, not a demonstrated build defect. Consider removing the unused file from the example project later.
5. **No favicon was supplied.** /favicon.ico returned 404. The HTML and CSS still loaded. Add an icon before public launch if desired.
6. **304 responses are normal.** They mean the browser can reuse cached files; they do not indicate a failed build.
7. **Reload enabled is not proof of reload working.** The server reports the feature enabled, but the operator has not yet confirmed automatic browser refresh after an edit.
8. **Sample dashboard values are not telemetry.** The starter currently says "Services: 3 online", "Alerts: 0 active", and "Build: ready". These are static placeholders and must be clearly labelled as demo data when customised.

No reproducible MANGANI core failure was established in this session.
